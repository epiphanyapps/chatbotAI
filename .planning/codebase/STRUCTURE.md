## Directory Purposes

**personalities/:**
- Purpose: Modular personality system defining distinct AI personas and their behavior
- Contains: Abstract base classes, concrete personality implementations, personality manager
- Key files:
  - `base_personality.py` - PersonalityBase (abstract), HotwifePersonalityBase (market-specific base)
  - `hotwife_dominant.py` - HotwifeDominantPersonality (Sophia concrete implementation)
  - `__init__.py` - PersonalityManager for personality registration and switching
- Pattern: Plugin architecture where new personalities extend base classes

**terraform/:**
- Purpose: Infrastructure provisioning and management for DigitalOcean deployment
- Contains: Terraform configuration files organized by environment and module
- Key files:
  - `main.tf` - Provider config, locals, high-level resources
  - `variables.tf` - Input variable definitions
  - `outputs.tf` - Output values for consumption by other configs
  - `modules/*/main.tf` - Specific infrastructure component definitions
  - `environments/*/` - Environment-specific variable overrides
- Pattern: Modular infrastructure design with environment-specific configurations

**nginx/:**
- Purpose: Reverse proxy and SSL/TLS termination configuration
- Contains: Nginx server blocks, SSL configuration, upstream routing
- Key files:
  - `nginx.conf` - Main nginx configuration (referenced in docker-compose.yml line 74)
- Purpose: Routes traffic to FastAPI backend, handles SSL certificates, serves static content

**.planning/codebase/:**
- Purpose: GSD framework output directory for codebase analysis documents
- Contains: Auto-generated architecture, structure, conventions, testing, and concerns documentation
- Key files: ARCHITECTURE.md, STRUCTURE.md, CONVENTIONS.md, TESTING.md, CONCERNS.md
- Generated by: `/gsd:map-codebase` command

**.claude/:**
- Purpose: GSD framework integration and Claude Code tool configuration
- Contains: Agent definitions, custom commands, hooks, framework files
- Pattern: Framework tooling (not application code)

**deployment-scripts/:**
- Purpose: Helper utilities for deployment and setup
- Contains: Shell scripts for initialization, environment setup, deployment automation

**.github/workflows/:**
- Purpose: GitHub Actions CI/CD pipeline configuration
- Pattern: Automated testing, building, and deployment on git events

## Naming Conventions

**Files:**
- Python files: `snake_case.py` (e.g., `multi_personality_bot.py`, `base_personality.py`, `hotwife_dominant.py`)
- Configuration: descriptive names (e.g., `docker-compose.yml`, `nginx.conf`, `requirements.txt`)
- Documentation: ALL_CAPS with underscores or descriptive (e.g., `ARCHITECTURE.md`, `SAAS_BUSINESS_PLAN.md`)
- Scripts: executable with shebang (e.g., `deploy-free.sh`, `github-to-gsd.sh`)

**Directories:**
- Python packages: `lowercase_with_underscores` (e.g., `personalities/`)
- Infrastructure: descriptive names (e.g., `terraform/`, `nginx/`, `deployment-scripts/`)
- Configuration: dotted prefix for hidden config (e.g., `.claude/`, `.github/`, `.planning/`)

**Python Classes:**
- Abstract/Base: `Descriptive` + `Base` suffix (e.g., `PersonalityBase`, `HotwifePersonalityBase`)
- Concrete: `Descriptive` + marker (e.g., `HotwifeDominantPersonality`, `MultiPersonalityIntimateBot`)
- Manager/Coordinator: `Noun` + `Manager` suffix (e.g., `PersonalityManager`)

**Python Methods:**
- Queries/Getters: `get_` prefix (e.g., `get_personality()`, `get_confirmation_style()`, `get_response_modifiers()`)
- Actions/Handlers: verb prefix (e.g., `handle_commands()`, `generate_and_send_response()`, `switch_personality()`)
- Checks: `is_` or `has_` prefix (none in current code)
- Create/Initialize: `create_` or `_initialize_` prefix (e.g., `create_personality_enhanced_responses()`)

**Python Variables:**
- Constants: ALL_CAPS (e.g., `TELEGRAM_TOKEN`, `TELEGRAM_API`, `MODEL_NAME`, `OLLAMA_URL`)
- Instance variables: snake_case (e.g., `self.training_data`, `self.conversation_history`, `self.personality_manager`)
- Local variables: snake_case (e.g., `user_id`, `response_mode`, `good_matches`)
- Private: Leading underscore for internal methods (e.g., `_register_personalities()`)

## Where to Add New Code

**New Feature (Core Functionality):**
- Primary code: `multi_personality_bot.py` - Add to bot class or create new service module in root
- Supporting personality logic: `personalities/` - Extend base classes or add new personality implementation
- Entry point integration: Add command handler in `handle_commands()` or response pipeline in `generate_and_send_response()`
- Configuration: Add environment variables to `docker-compose.yml` and terraform modules
- Tests: Create `tests/` directory with `test_*.py` files (not yet established)

**New Personality/Character:**
- Implementation file: `personalities/new_personality_name.py`
  - Inherit from `HotwifePersonalityBase` or `PersonalityBase`
  - Implement: `get_personality_name()`, `get_confirmation_style()`, `get_story_themes()`, `get_response_modifiers()`, `add_personality_flair()`
- Register: Add to `PersonalityManager._register_personalities()` in `personalities/__init__.py` (lines 27-45)
- Example pattern: Follow `hotwife_dominant.py` structure with character names, locations, key phrases, confirmation templates

**New Infrastructure Component:**
- Terraform module: `terraform/modules/new_component/`
  - Files: `main.tf`, `variables.tf`, `outputs.tf`
- Module usage: Add to environment-specific configs in `terraform/environments/*/`
- Example pattern: Follow existing modules (database, networking, app-platform, monitoring)

**Utilities/Helpers:**
- Shared helpers: Create `utils/` directory with `helper_name.py` modules
- Import pattern: From bot or personality classes, import via `from utils.helper_name import function_name`
- Example: Configuration parsing, string utilities, API helpers

**Deployment Scripts:**
- Location: `deployment-scripts/` for shell scripts and deployment utilities
- Pattern: Executable scripts with clear purpose, documented usage
